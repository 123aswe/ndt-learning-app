# NDT 刷题 · 微信小程序端

用 **web-view 承载现有 H5**（后端托管的 `/app/`），因此 **界面与 App 完全一致，一行 UI 都没有改**。
小程序本身只负责：加载、加载失败兜底、切换后端地址。

---

## 一、目录结构

```
miniprogram/
├── project.config.json     开发者工具项目配置（urlCheck:false = 本地调试不校验域名）
├── app.json                全局配置：只有 1 个页面 + 顶部导航栏样式
├── app.js                  入口：地址探测 + 探测诊断 + 网络状态 + 版本更新 + 开调试模式
├── app.wxss                全局样式（只服务「连接中」界面与兜底页）
├── sitemap.json            搜索索引配置
├── config/
│   └── env.js              ★ 环境配置：本地服务 / 局域网 / 公网隧道 / 腾讯云
└── pages/index/            唯一页面 —— web-view 承载 H5
    ├── index.js            三态（连接中 / web-view / 兜底）+ 改地址 + 一键开调试
    ├── index.json          页面配置
    ├── index.wxml          三态界面（绝不白屏）
    └── index.wxss          页面样式
```

## 二、后端地址怎么配（**自动探测**，一般不用管）

小程序**不写死地址**：启动时按顺序试「手填地址 → 上次连通的 → `config/env.js` 里的种子 →
后端报过的地址」，谁能连通（`/api/health` 返回 200）就用谁；连通后再向后端要一份当前可用地址
（`GET /api/access-info`，内容就是**管理后台「网络访问」卡片上那三条地址**），存下来供下次优先使用。

→ 所以**后台那边显示什么地址，小程序下次打开就跟随什么地址**：局域网 IP 变了、
公网隧道重启换了域名，都不用改任何代码。

`config/env.js` 只有两处需要维护：

| 项 | 说明 |
| --- | --- |
| `DEFAULT_ENV` | 默认**第一个**试哪个环境。本机开发用 `local`；将来纯云端运行改成 `cloud` |
| `ENVS.<env>.appUrl` | **探测种子**。`local` 固定 `http://127.0.0.1:8000/app/`；`lan` / `tunnel` / `cloud` 留空即可（靠自动探测）。真机首次探不到时，在 `lan` 里填一次电脑局域网 IP，这样**所有手机**就开箱即用了 |

探测失败时（兜底页）有三种补救手段：

1. **重新连接** —— 按当前优先级再探一遍
2. **自动探测服务器** —— 忽略手填地址，纯自动找一遍（手填地址填错时用）
3. **修改服务器地址** —— 手填一次并记住；点「恢复自动探测」可清掉
4. 电脑上跑通后，用小程序右上角「**转发**」把带地址的链接发给自己 —— 手机上打开即自动带上

## 三、本地跑起来

1. 启动后端：`server/启动服务.bat`（或 `.venv\Scripts\python.exe main.py`）
2. 确认前端已构建：项目根 `dist/index.html` 存在（没有就 `npm run build`）
3. 微信开发者工具 → 导入项目 → 目录选 **`miniprogram/`** → AppID 用**你自己的小程序 AppID**
4. 详情 → 本地设置 → 勾选 **「不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书」**
5. 直接就能跑（地址自动探测）

**⚠️ 要在手机 / PC 上看，不要点「预览」** —— 第 4 步那个开关**只在模拟器生效**。
「预览 / 体验版 / 正式版」是真机环境，**强制域名校验**，`web-view` 还要求 https + 业务域名，
所以点「预览」基本就是**白屏**。正确做法二选一：

| 方式 | 做法 |
| --- | --- |
| **① 真机调试**（推荐） | 工具栏点「**真机调试**」而不是「预览」，手机扫码。它会继承工具里的「不校验合法域名」 |
| **② 预览 + 开调试模式** | 「预览」扫码后，手机上右上角「**…**」→「**开发调试**」→ 打开调试（兜底页有「开启调试模式」一键按钮） |

两种都要求：手机与电脑同一 WiFi + 后端管理后台打开「网络访问 → **局域网**」开关。

## 四点五、真机 / PC 预览空白（工具里正常）

不是代码问题，而是环境差异。现在页面**有三态、不会再白屏**，失败时会显示**真实原因**和**诊断信息**：

| 兜底页标题 | 含义 |
| --- | --- |
| **被小程序的域名校验拦下** | 预览/体验版/正式版强制校验，未配域名的地址被客户端拦掉（最常见） |
| 手机当前没有网络 / 连不上服务器 / 服务器没正常响应 / 页面加载失败 | 分别对应断网、地址或后端问题、接口非 200、`binderror` 的原始信息 |

> 兜底页上有「**开启调试模式**」按钮（调 `wx.setEnableDebug`，仅开发版/体验版有效），
> 以及「**诊断信息**」块（运行环境 / 基础库 / AppID / 每个候选地址的探测结果），可复制。
>
> 完整排查流程（含**个人主体不支持 web-view**这条硬约束）见项目根 `小程序-操作说明.md` 第八节。

## 四、正式发布的前提（重要）

微信规定：`web-view` 加载的网页域名必须

- 已 **ICP 备案**，且备案主体与小程序主体一致
- 使用 **HTTPS**
- 在小程序后台配置为 **业务域名**（下载校验文件放到域名根目录验证）

且 **个人主体小程序不支持 `web-view` 组件**（个人号后台根本没有「业务域名」入口）。
所以正式发布需要：**非个人主体小程序（企业 / 个体工商户 / 组织）+ 已备案的 HTTPS 域名**。

> 「个体工商户」也算非个人主体，有营业执照就能用，是个人开发者成本最低的合法路径。

## 五、已知限制

- **真机 / PC 预览空白**（工具里正常）：见上一节。根因是「预览 = 真机环境，强制域名校验」，
  不是代码问题；正式发布必须满足「非个人主体 + 备案 HTTPS 域名 + 业务域名」。

- **真机首次运行**：手机本机没有任何缓存，只能从 `env.js` 的种子（默认只有 `127.0.0.1`，手机上不通）开始试，
  所以首次可能落到兜底页 —— 手填一次电脑局域网 IP（或从电脑转发带地址的链接）即可，之后一直记住。
  想彻底免掉这一步：在 `config/env.js` 的 `ENVS.lan.appUrl` 里填上电脑局域网 IP（属于打包配置，所有手机通用）。
- 音乐「跨页面后台播放」在 web-view 内仍然有效（App 是单页应用，没有页面跳转），
  但**退出小程序后音频会停** —— 小程序的后台音频要走原生 `BackgroundAudioManager`，属于后续增强项。
- 顶部原生导航栏由小程序提供（标题「NDT无损检测刷题」），改 `app.json` 的 `navigationBarTitleText` 即可。
